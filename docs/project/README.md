# docs/project/

**Purpose:** Stable project identity, mission, scope, and decision constraints.

**Data stored here:** Markdown only. These files describe what the project is,
why it exists, what must not change without review, and how future tools should
interpret the rest of the repository.

## Portals

| Portal | File | Type | Holds |
|---|---|---|---|
| `description____` | [description.md](description.md) | Markdown | Finalized project description and source-of-truth hierarchy |
| `architecture____` | [architecture.md](architecture.md) | Markdown | Technical stack, decisions with rationale, trust-boundary mapping |
| `roadmap____` | [roadmap.md](roadmap.md) | Markdown | Phase-by-phase build order from now to a finished project |

## Flow

Start with [description.md](description.md) before planning major changes. If a
brainstorming document changes the project direction, promote the accepted part
back into this folder so implementation plans do not depend on raw notes.
