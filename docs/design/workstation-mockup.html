What to look at

    
    
      
  • One question at a time, in words. The left rail is the queue; the centre asks a single plain-language question taken straight from fields.yaml. Nothing here is hardcoded — every field name, unit, range, and question comes from the spec file.
    • 
      
  • The diff before you commit to it. “What this will change” shows the exact line in the exact file, with the trailing comment intact. That is the surgical writer's output made visible, and it is what makes a save trustworthy enough to run twenty-one times in an evening.
    • 
      
  • A value out of range warns and still saves. Try 0.4 in the input. Measurements are facts; the design being wrong is a separate problem, reported separately.
    • 
      
  • Consequence is visible beside the input. Use the Report state control in the blue bar to see all-clear, a warning, and a failure. In the real app that panel is whatever the server returns from validate.py — no check text or threshold is duplicated in the front end.
    • 
      
  • Room is left for Phase 7. The dashed slot is where the component model with the highlighted dimension goes. Reserving it now means the layout does not get rebuilt later.
